# Evidence and sources

Reviewed 2026-09-28. Recommendations are design judgments unless explicitly marked as measured. These sources support methodology and capabilities; none demonstrates that an untrained GridOracle replacement will outperform its baselines. Recheck provider terms and APIs before implementation.

## Repository and empirical evidence

- **E1 — Checkout:** commit `934c235`, dated 2026-03-23. Review covers the tracked application, tests, SQL migrations, containers and CI. Existing untracked `.codex/` and `.ticket-workflow/` were left untouched.
- **E2 — Baseline experiment:** [method, attribution and reproduction](evidence/README.md), [computed results](evidence/baseline-summary.json), [reproduction program](evidence/baseline_audit.py), and [40 original public responses](evidence/jolpica-2022-2025.tar.gz). 92 races, 1,838 result rows; qualifying baseline covers 91 races. No GridOracle model was trained or benchmarked.
- **E3 — Verification:** 205 pipeline tests and 25 API tests passed; three frontend tests passed. Python lint/format, frontend lint/format/typecheck and production build passed. API tests required an isolated dependency environment because the existing `.venv` lacks FastAPI. See [review](REPOSITORY_REVIEW.md).
- **E4 — Homelab:** user-provided host catalog, corroborated by read-only inspection of [Hosts](/Users/pieterohearn/Documents/Projects/homelab-wiki/Reference/Hosts.md), [Services](/Users/pieterohearn/Documents/Projects/homelab-wiki/Reference/Services.md), [Routes](/Users/pieterohearn/Documents/Projects/homelab-wiki/Reference/Routes.md), [Firewall](/Users/pieterohearn/Documents/Projects/homelab-wiki/Reference/Firewall.md), [Prometheus](/Users/pieterohearn/Documents/Projects/homelab-wiki/Services/Prometheus.md) and [Find a bottleneck](/Users/pieterohearn/Documents/Projects/homelab-wiki/Runbooks/Find%20a%20bottleneck.md). ## Data providers

| ID  | Primary source                                                                                                                                                                             | What it supports and what it does not                                                                                                                                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | [Jolpica API documentation](https://github.com/jolpica/jolpica-f1/blob/main/docs/README.md)                                                                                                | Ergast-compatible results, qualifying, sprints, standings and identity endpoints; pagination maximum 100; custom identifying user agent. Historical records do not establish publication time.                                                                                                                      |
| S2  | [Jolpica rate limits](https://github.com/jolpica/jolpica-f1/blob/main/docs/rate_limits.md)                                                                                                 | Currently 4 requests/second and 500/hour unauthenticated; limits may change. Cache and pace requests.                                                                                                                                                                                                               |
| S3  | [Jolpica terms](https://github.com/jolpica/jolpica-f1/blob/main/TERMS.md)                                                                                                                  | Non-commercial availability and CC BY-NC-SA 4.0 data license; no availability/correctness guarantee. Commercial use requires a separate check with the provider.                                                                                                                                                    |
| S4  | [FastF1 upstream project](https://github.com/theOehrly/Fast-F1), [maintainer's data-availability statement](https://pypi.org/project/fastf1/2.1.4/)                                        | Session timing, weather, tyres and telemetry; detailed live-timing history starts in 2018. The coverage statement is an older maintainer release: verify actual completeness per session instead of assuming all 2018+ data exists.                                                                                 |
| S5  | [OpenF1](https://openf1.org/)                                                                                                                                                              | Optional historical coverage since 2023; public documentation describes a free historical tier and paid live access. Do not make live access a dependency of this free product.                                                                                                                                     |
| S6  | [Open-Meteo pricing](https://open-meteo.com/en/pricing)                                                                                                                                    | Free non-commercial tier with rate limits and no uptime guarantee. Suitable candidate for a non-commercial fan product, subject to attribution and current terms.                                                                                                                                                   |
| S7  | [Open-Meteo historical forecasts](https://open-meteo.com/en/docs/historical-forecast-api), [single runs](https://open-meteo.com/en/docs/single-runs-api)                                   | Historical weather products differ. Single-run coverage is model-dependent; the page lists IFS from March 2024 and most others from April 2026, and mentions hindcasts. Initialization time alone does not establish that a forecast existed publicly at that time. Verify original-run provenance and release lag. |
| S8  | [OpenWeather five-day forecasts](https://openweathermap.org/api/forecast5)                                                                                                                 | Forecast intervals are three hours apart. Select the interval(s) covering the event; the first interval is not inherently the race forecast.                                                                                                                                                                        |
| S9  | [FIA regulations index](https://www.fia.com/Regulations/F1), [FIA/F1 Cadillac approval](https://corp.formula1.com/fia-and-formula-1-joint-statement-regarding-2026-eleventh-team-process/) | Season-specific rules and changing grid composition are real requirements. Pin applicable published sporting regulations per season; do not hard-code a universal 20-driver field or points system.                                                                                                                 |

## Modeling and engineering

| ID  | Primary source                                                                                                                                                                                                                                                                            | Application to this design                                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S10 | [scikit-learn: common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html)                                                                                                                                                                                                     | Fit preprocessing and choose features without using held-out data.                                                                                                                                                          |
| S11 | [scikit-learn: TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)                                                                                                                                                           | Temporal evaluation trains on earlier observations. GridOracle needs its own race-grouped chronological splitter: ordinary row-level splitting would divide race fields and calendar intervals are unequal.                 |
| S12 | [scikit-learn: probability calibration](https://scikit-learn.org/stable/modules/calibration.html)                                                                                                                                                                                         | Separate calibration data, proper probability scores, reliability diagrams; Brier score alone is not a pure calibration measure.                                                                                            |
| S13 | [XGBoost: learning to rank](https://xgboost.readthedocs.io/en/stable/tutorials/learning_to_rank.html)                                                                                                                                                                                     | Race-grouped ranking is implementable using `qid`. Ranker scores are not probabilities. Invert finishing ranks to relevance if using NDCG and document its top-heavy weighting.                                             |
| S14 | [Grinsztajn et al., NeurIPS 2022](https://papers.neurips.cc/paper_files/paper/2022/file/0378c7692da36807bdec87ab043cdadc-Paper-Datasets_and_Benchmarks.pdf)                                                                                                                               | Empirical reason to include boosted trees in tabular experiments. This is not proof that trees always beat modern neural models or that a particular F1 model will win.                                                     |
| S15 | [Weng and Lin, JMLR 2011](https://www.jmlr.org/papers/volume12/weng11a/weng11a.pdf), [PlackettLuce authors' documentation](https://hturner.github.io/PlackettLuce/)                                                                                                                       | Probabilistic ranking and Bayesian skill estimation are plausible alternatives. Assumptions and F1 suitability still require testing.                                                                                       |
| S16 | [WCAG 2.2](https://www.w3.org/TR/WCAG22/)                                                                                                                                                                                                                                                 | Contrast, keyboard use, focus, reflow and accessible targets. Aim for AA and test complete user journeys, not just automated scans.                                                                                         |
| S17 | [Alembic tutorial](https://alembic.sqlalchemy.org/en/latest/tutorial.html)                                                                                                                                                                                                                | Versioned database upgrades on existing installations. Baseline/adopt the current schema before changing it.                                                                                                                |
| S18 | [Docker multi-platform builds](https://docs.docker.com/build/building/multi-platform/)                                                                                                                                                                                                    | Separate ARM64 and AMD64 image support is relevant to the Pis and Proxmox host. Build success is not a substitute for native runtime testing.                                                                               |
| S19 | [PostgreSQL backup and restore](https://www.postgresql.org/docs/current/backup.html)                                                                                                                                                                                                      | Logical/physical backups and continuous archiving are distinct mechanisms. A Docker volume or another directory on the same disk is not a recovery plan.                                                                    |
| S20 | [PyTorch training basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html), [installation](https://pytorch.org/get-started/locally/), [MPS](https://docs.pytorch.org/docs/2.14/notes/mps.html), [reproducibility](https://docs.pytorch.org/docs/2.14/notes/randomness.html) | Training workflow, backend availability and reproducibility limitations. Check an actually compatible build on the owner's GPU/Mac; do not assume bitwise equality across platforms or pin a version from a search snippet. |
| S21 | [MLflow experiment tracking](https://mlflow.org/docs/latest/ml/tracking/)                                                                                                                                                                                                                 | Optional local run/parameter/metric/artifact tracking. A separate always-on service is not necessary to maintain an experiment manifest.                                                                                    |

Source links were inspected during this review; web retrieval of the rendered FastF1 documentation returned HTTP 403, so its upstream repository and maintainer package page were used. Version numbers in live documentation may differ from the repository's pinned packages.
