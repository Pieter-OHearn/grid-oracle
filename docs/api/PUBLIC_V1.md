# Public v1 foundation — WP11

The public service is read-only. The source DTOs are `api/schemas/public.py`;
`public-v1.schema.json` and `dashboard/src/public/{contract.ts,schema.json}`
are generated by `python -m scripts.generate_public_client`. Run the same
command with `--check` to detect drift. JSON schema also validates responses
in the browser before they enter the shared query cache.

## Resources

| GET resource | Response |
| --- | --- |
| `/api/v1/seasons` | Supported years from persisted calendars/rulesets |
| `/api/v1/seasons/{year}` | Selected ruleset and explicit coverage |
| `/api/v1/seasons/{year}/events` | Event index, lifecycle and published horizon coverage |
| `/api/v1/seasons/{year}/events/{id}` | One event; IDs from another season return 404 |
| `/api/v1/seasons/{year}/events/{id}/sessions` | Latest persisted revision per session kind |
| `/api/v1/seasons/{year}/events/{id}/forecast?horizon=pre_weekend\|post_qualifying` | Discriminated published/absent selection |
| `/api/v1/seasons/{year}/events/{id}/runs` | Approved public runs only |
| `/api/v1/seasons/{year}/events/{id}/runs/{run_id}` | Exact approved immutable run; unpublished IDs return 404 |
| `/api/v1/legacy/races/{id}` | Resolve the actual season of a legacy numeric race ID |

A persisted WP03 `forecast_publications` pointer is the approval boundary.
There is no highest-model-ID/latest-run/legacy fallback. Only `verified` and
`observed` publications without result-linked lineage are eligible. The
pointer's event/horizon must match the run. Invalid published fields produce a
sanitized, retryable 503; they are never reinterpreted as absent publications.
Publication timing and append-only ownership remain WP03/WP04 responsibilities.
WP11 does not select a champion, promote a model, publish a run, or mutate data.

Entry producers must persist `ForecastEntry.entry_key = "entry:<event_entries.id>"`
with the exact event-entry revision used at issue time. Only numeric finite
`output.win_probability` in [0,1], or explicit null, crosses the API boundary.
Ranker confidence/positions are not probabilities. Missing probability keys
remain null; other output keys, manifests, model paths, hashes, job errors and
research metadata are omitted. Entry IDs must belong to the run's event. Old
run formats without this binding are explicitly unavailable/invalid until an
operator-approved producer/import mapping exists; no mapping is inferred.

Names resolve from date-valid, display-marked `entity_aliases.provider_key`,
using the event date and half-open alias validity. Missing or ambiguous names
are null. Mutable current driver/team/circuit display names never substitute
for historical labels. The integrated domain has no temporal team-color field;
`team_color` stays null and the UI uses neutral strips paired with visible team
names. Season-specific colors can be added through a future versioned contract,
without copying current branding into past seasons. No backfill is performed.

## Data semantics

`ForecastSelection` is a discriminated union. `published` requires a run;
`unavailable` has `reason=no_published_forecast` and a null run. Absence is a
successful 200 response; API failure is a typed error envelope with HTTP
status 404/422/503 and `retryable`. SQL/validation failures never return SQL,
credentials or internal paths. Error responses are `Cache-Control: no-store`.
All registered public operations are GET; CORS only permits GET.

Coverage is `complete`, `partial`, `unknown` or `empty`, with nullable observed count,
nullable expected count and reason. An empty array has no inferred total or
ranking. Null is Unknown; actual zero remains 0%. Invalid probabilities fail;
non-unit published totals are displayed with a warning and never normalized.

Freshness includes original cutoff, issue and source-availability timestamps.
`verified_as_of_cutoff` describes a verified immutable snapshot, not current
wall-clock freshness. `observed` timing remains unknown pending verification;
late/missing timing is labelled explicitly. The DTO reserves `stale` for a
future source-specific freshness policy; WP04 supplies no universal staleness
threshold, so WP11 invents none. Historical snapshots do not age into false
staleness merely because the event happened years ago.

## Browser and component contracts

`/seasons/{year}/events/{id}` and `/field` or `/sessions` are refresh-safe.
`weekend`, `events`, `record`, `methodology` and `sources` are season-scoped.
The URL is the global season authority; switching season changes the shell and
all query keys, preserves horizon/journey, and resolves an event in the target
season instead of reusing an unrelated numeric ID. Legacy `/race/{id}` resolves
through the versioned legacy resource. Unknown IDs remain explicit 404 states;
`/race/{id}/results` opens that event's canonical results URL with an explicit
unavailable view (result presentation is outside this foundation).

The shared cache deduplicates active requests, retains responses for 60 seconds
and prunes inactive entries at 100 keys. AbortController cancels when the last
consumer leaves; generation checks discard late responses. Errors stay visible
until retry/new subscription, with no previous season's percentages retained.
The runtime schema rejects malformed success responses. Empty and unavailable
states differ from transport errors and loading. Retry restores heading focus.

Production imports WP10 tokens/fonts and the reusable Panel component. Typed
`ForecastContext`, `FieldTable`, `QueryNotice` and `Notice` adapt public data
through the extracted shared Panel, without importing the sample fixture. Table headers,
captions and named scroll regions preserve meaning at 320px. Native navigation,
horizon buttons, season select, skip link and route/history focus support
keyboard journeys. A chart loads only on explicit request; the semantic table
remains the accessible equivalent. No public model explanations or performance
scorecards are implemented. `record` is publication coverage only.

## Build and rollback

`cd dashboard && bun install --frozen-lockfile && bun run build` packages static
assets. The multi-stage Dockerfile serves `dist` with Nginx on port 3000;
`nginx.conf` proxies only `/api/v1/` to the API, uses SPA fallback for season
URLs and immutable caching for hashed assets. Vite development/preview uses the
same API prefix with a local proxy to 8000. Font licenses accompany the static assets under `/font-licenses/`. No deployment is authorized.

Nginx defers API resolution to Docker DNS (`127.0.0.11`, five-second DNS cache).
It serves the app when the API is missing and re-resolves a recreated API without
a frontend restart; the client exposes proxy failures as retryable errors.
The default Compose sample runs `scripts.migrate_sample` as a separate one-shot
service after database health and before API startup. This opt-in bridge only
accepts the committed demo calendar on the dedicated disposable database;
it does not publish legacy predictions or migrate during API startup.
Real database upgrades retain the backup-gated operator CLI.

Legacy UI is retained behind build-time `VITE_GRIDORACLE_LEGACY_UI=1`; the old
backend routes require `GRIDORACLE_LEGACY_API=1` on a private/local operator
service. Neither is enabled in the public container. The old/new flag exists
for parity/rollback inspection, not public exposure of unverified legacy data.
Rollback public serving by reverting WP11 or rebuilding the prior release while
retaining the immutable database. No migration or data deletion is required.

## Reproduce browser evidence

Create a fresh **synthetic** local DB explicitly (the builder refuses existing
schemas): `python -m api.tests.public_fixture --database /tmp/wp11.sqlite`.
Run the API with `DATABASE_URL=sqlite:////tmp/wp11.sqlite uvicorn api.main:app`,
build the dashboard and run `bunx vite preview --host 127.0.0.1 --port 4173`.
With Playwright resolvable through NODE_PATH, run
`node scripts/wp11_browser.cjs`. `WP11_PREVIEW_URL` and `CHROME_EXECUTABLE`
can override the local preview/browser. No fixture is loaded by application
startup. The screenshots clearly identify synthetic acceptance events/entries.
See `docs/design/evidence/wp11` for retained evidence and limitations.
