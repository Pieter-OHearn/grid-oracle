### Required delivery contract

Follow the established homelab deployment boundary: GridOracle's repository builds and
tests immutable OCI images, releases them to GHCR, and records their version and
digest. The homelab repository owns the GridOracle service manifest and Compose stack;
a reviewed homelab PR promotes a specific released digest. The existing self-hosted
deployer runner deploys only the merged homelab configuration after its normal plan,
risk gate and verification steps. It does not build GridOracle source, train models,
or consume a mutable image tag.

The agent must design and evidence a model-bundle manifest that identifies the model,
training data, feature schema, calibration and artifact hashes. Runtime recovery must
load that declared bundle without access to the training machines. Use Quro's GHCR
image release and digest-pinned homelab stack as the reference pattern; do not copy
its application-specific services or automatic-update mechanism.

## Decisions and blockers

WP13 placement/storage/limits are package-local proposals, not new owner-approved
cross-package decisions. The measured ARM Pi is selected for the proposal;
public domain/ingress, SOPS provisioning, dedicated HDD backup directory/access,
representative loaded-host measurements and a real production bundle remain
production activation conditions. No authorization for a live apply or public
route is inferred from this assignment.

Known implemented prerequisite limitation: WP04's durable feature/predict/publish
adapter deliberately blocks; WP09 retains the evaluated baseline without a
production refit. Synthetic saved-publication recovery is valid operations
evidence and is not production model/inference/backfill quality evidence.
Application/DB spans remain uninstrumented; existing edge tracing is reused.
Native PR CI built both architectures, then found Linux UID copy/cleanup failures; repaired by same-UID container copy/scoped temporary cleanup. The failed `v0.1.0-wp13.1` staging tag is retained, not reused, and published no release.

No infrastructure mutation was performed. Normal Docker metadata timed out;
using an isolated Docker client configuration succeeded. Other initial local
drill failures (tmpfs quoting, fixture writer permissions, internal network
host access, simulated backfill time) are repaired and documented.

## Migration, backfill and rollback

No new migration revision, real DB initialization/backfill, forecast mutation,
training or deployment. New one-shot migration tooling consumes existing SQL
baseline/Alembic only after a pinned coordinated backup. API startup never
upgrades. Routine rollback is a reviewed homelab prior-image/bundle promotion;
incompatible schema recovery restores the verified pre-upgrade set into a new
environment. Destructive downgrade is not a serving rollback.
