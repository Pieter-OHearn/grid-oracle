## Assignment and boundaries

The owner assigned part 1 on 2026-10-09: everything a live, private
deployment needs before prospective shadowing can start. Shadowing itself
(six eligible races, both horizons) is calendar time and stays open in this
package after part 1 integrates. The remaining 2026 races after Singapore
(2026-10-11) are Austin (10-25), Mexico City, São Paulo, Las Vegas, Qatar
and Abu Dhabi (12-06): six, if part 1 is deployed before the Austin
pre-weekend cutoff.

Part 1 scope:

1. **Production issuance adapter** for the WP09-retained fixed baselines
   (`standings` pre-weekend, `qualifying` post-qualifying), replacing the
   blocked feature/predict/publish handlers. Built from WP14's test-only
   replay adapter, but on live Jolpica data through `ProviderAdapter`
   (immutable raw snapshots, quarantine, rate budget): calendar and
   sessions, the event field, race-only standings at the cutoff, Grand Prix
   qualifying, results with numbered revisions, and evaluation. FastF1 and
   the legacy mutable `predictions` path are not used.
2. **The first production bundle**: a fixed-baseline model artifact with its
   closure, written by a command, and its manifests recorded in the
   production database by a second, idempotent command.
3. **Runtime wiring**: the scheduler reconciles the live calendar; the worker
   runs the production handlers. Both hold a shared maintenance lock per
   tick, so a coordinated backup can quiesce writers without stopping
   containers.
4. **Backups**: a `backup` action that takes the exclusive maintenance lock,
   writes a `pg_dump` custom archive with the PostgreSQL 16 client, seals the
   set, verifies it, publishes it atomically and keeps a bounded number of
   local sets; a loop for a sidecar; a status file that `/metrics` reports.
5. **Database roles**: a reviewed one-off that creates the API reader and the
   worker roles from the deployment's URL secrets, with default privileges,
   never at serving startup.
6. **Release readiness**: docs (DEPLOYMENT, RECOVERY, MODEL_BUNDLE) and a
   stable `v0.1.0` release request to the owner.

Out of scope: public ingress, model promotion beyond the WP09 fallbacks,
training, and changes to the frozen WP06 protocol or WP09 decisions.

  entrants, carried forward as revision 1 entries; the qualifying
  classification revises it (a transfer closes one entry and opens another).
