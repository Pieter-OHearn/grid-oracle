# GridOracle repository review

2026-09-28 · Baseline commit `934c235` · Planning and evidence only; application behavior has not been changed.

## Assessment

The project has a useful foundation: separate API, pipeline and dashboard; PostgreSQL; real XGBoost training; shared preprocessing; model-version associations; mostly date-bounded historical features; ingestion upserts; and a substantial pipeline unit-test suite. Retain these useful boundaries while redesigning the domain and forecasting workflow.

The central problem is **forecast validity and reproducibility before model sophistication**. Current training, historical replay, publication and metric semantics cannot support a trustworthy public performance claim. XGBoost is already machine learning. Better experiments may choose a different model, but the existing defects would invalidate that model too.

This was a code and local-check review, plus a separate public-data experiment. No running GridOracle service, dataset, populated database or saved model was available locally. Docker inspection found only unrelated services; those were not inspected further. No attempt was made to start the production scheduler or run bootstrap, which could mutate data and publish hindsight predictions. UI findings are source-level findings and calculated color contrast, not a browser usability study.

## Implications from the real-data audit

Qualifying-order predictions over 91 races recover **65.93% of podium members**, but hit only **14.63% of exact positions**. Winner accuracy ranges from **45.45% to 68.18%** by season. A high-sounding podium percentage or a dominant-driver season alone is weak evidence of skill. The target engine must compare identical races at identical cutoffs against simple baselines and show uncertainty. [Reproduction and caveats](evidence/README.md)

The bootstrap's four historical seasons contain only 92 race events in this retrieved sample. The 1,838 driver rows share race-level conditions and are not 1,838 independent forecasting situations. More timing rows can improve features, but cannot manufacture independent race outcomes. This is why regularized models, chronological validation and realistic uncertainty matter more than model size. A custom model remains an excellent learning project; its deployment is evidence-gated.
